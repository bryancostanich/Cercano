This is one new method on the EXISTING agent service, not an updater listener:
ShutdownAgentWhenIdle waits without cancelling active work, refuses wrong PID or
missing tracking/lifecycle ownership, then retains the admission seal while the
normal standalone lifecycle stops the process. PID is an identity check, not
caller authentication. Older agents return Unimplemented without being stopped;
normal connections/version behavior and the legacy stop RPC remain available.

Standalone agent stop uses a caller-owned process-local request channel, avoiding
unsupported Windows self-interrupt. Embedded MCP has no standalone consumer and
must refuse the safe method. A side-effect-free regression reproduced the bad
nil-owner defaulting in partial worker code; it was corrected without starting
servers, models, network endpoints or touching configuration. A proposed test
that attempted real startup was replaced before it could execute.

The existing last-subscriber idle timer could bypass active work; a direct probe
reproduced it. It now obtains the same verified-idle admission seal and rechecks
subscribers before committing the lifecycle callback. User work is not cancelled
merely because a UI disconnects.

Worker host callbacks are joined after their turn context is cancelled, before
transport/process cleanup returns. Credential shared refreshes retain separate
activity through actual return and persistence, even when all waiters have left.
Credential/token/generation semantics were not changed by the lifetime hook.
